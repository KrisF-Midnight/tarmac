Chapter 5

Infrastructure

Everything Terraform creates for the application is one S3 bucket and one object — and the application repository declares neither of them.

Moving parts

Terraform 1.15.9 pinned in CI, AWS provider 6.x, an S3 backend locking with a lockfile rather than DynamoDB, and LocalStack pinned by digest standing in for AWS.

Resources

One bucket per application and environment, one object per config entry. Versioning, encryption and a public access block are constants, not variables. No IAM, no database, no queue.

Contract

app_name is validated at plan time because a bucket name is global and immutable; caller tags merge under the platform’s.

NameWhat it carries
app_nameNames and tags every resource. Three to 28 characters of lowercase letters, digits and hyphens, checked by a variable validation rather than by the API at apply
environmentOne of local, staging, production
configObject key to contents. Values reach plan output and state, so nothing secret belongs here
tagsMerged under the platform’s own, which win
Outputsconfig_bucket, config_bucket_arn, config_keys — only the first has a caller

Ownership

Every resource block lives in tarmac; the app repository holds a greeting and one module call. The source is a relative path into a sibling checkout, where a version constraint belongs.

State

S3, with the lock beside the state file rather than a DynamoDB table. Bucket, key and region arrive at init from a per-environment file, so a new environment adds files rather than Terraform.

Access grant

No IAM. The pod gets a static key pair from a Secret in git. The app’s S3 client cannot assume a role, so a real account changes how it authenticates, not only where the Secret comes from.

Where to look
  • tarmac/infra/modules/app-dependencies/ — the bucket, its three non-negotiable settings, and the four inputs
  • greeter/infra/main.tf — what the application decides for itself: a greeting, and one module call to get somewhere to keep it
  • greeter/infra/env/ — backend config and variables per environment; adding one adds files here, not Terraform
  • tarmac/localstack/ — the emulator, and the init hook that creates the state bucket a backend cannot create for itself
  • tarmac/gitops/local-aws/credentials.yaml — the key pair the pod is handed, and why it sits in git
