Chapter 2

CI

Nine checks over one commit, run in a fixed order by a program rather than a YAML script — so a laptop can run the same logic.

Moving parts

GitHub Actions runs the workflow, but the logic is a TypeScript program on Bun. docker build builds, Trivy scans, ghcr.io stores, and a short-lived GitHub App token writes back.

Trigger & inputs

An application calls this pipeline on every push and pull request, against its own commit, supplying the tarmac ref, the app directory, two App secrets, a typecheck and a test script, and a root Dockerfile.

Checks

A gate is a named check that can fail the run; one whose subject is absent is skipped, not passed.

Gates, in run orderWhat it establishes
base-image, policyThe base image is pinned to an exact digest, and the Terraform and Kubernetes files satisfy the rules — though policy also lists advisory findings and passes anyway. blocking
deps, typecheck, unit-testsThe lockfile installs clean, the types check, the app’s own suite passes. blocking
infra, image-buildEvery Terraform module is formatted and valid; the image builds. blocking
securityTrivy scans the image just built. Findings are recorded, never enforced — disclosures arrive on their own schedule, not in the diff. reporting
image-publishPushed to ghcr.io, GitHub’s container registry, tagged with the commit SHA. Push events only, so it never blocks a pull request. blocking

Orchestration & severity

Gates run cheapest-first, so the least expensive failure surfaces soonest. security needs image-build’s image; typecheck and unit-tests need deps. Blocking failures do not abort the rest.

Artefact & publication

The release job writes the repo@sha256 reference into tarmac’s own manifests under gitops/.

Credentials & trust

The release token is valid for one hour and one repository. On a push the gates job also holds a registry credential while the app’s tests run.

Reporting & reproducibility

Findings land in the job summary, never on the pull request. make ci runs the same entrypoint without the publish gate.

Where to look
  • tarmac/.github/workflows/ci.yml — the shared pipeline: gates on every event, release only on the default branch
  • tarmac/gates/src/registry.ts — the nine gates in run order, and the three things an app must provide
  • tarmac/gates/src/verdict.ts — what makes a run fail, kept pure so it is testable
  • tarmac/promote/src/ — writes the image reference into tarmac’s own gitops/ tree; there is no separate deployment repository
  • tarmac/.github/workflows/self.yml — the platform’s own pipeline, where the gate-matrix drift check runs
