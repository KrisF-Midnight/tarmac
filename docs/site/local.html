Chapter 6

Local

Everything here runs on a laptop with no cloud account, which buys reproducibility and costs you IAM — the one control a real deployment leans on hardest.

Moving parts

kind runs a single-node cluster on Docker, LocalStack stands in for AWS beside it, ingress-nginx answers on port 8080, and a Makefile drives the lot. No Helm, no Skaffold.

Entrypoint

make up runs seven steps in a fixed order: cluster, admission policies, emulator, Terraform, ingress, Argo CD, endpoint. Each is idempotent, so it doubles as the repair command.

Known gap

Argo CD syncs pushed main, not this working tree. An uncommitted change under gitops/ is invisible to the cluster.

Cluster & cloud substitute

kind gives one node, digest-pinned at Kubernetes 1.36.1. LocalStack runs beside the cluster in Docker rather than inside it, serving only s3 and s3control.

Access

kind maps node port 80 to host 8080, so ingress-nginx serves the app at localhost:8080 — no hostname, no TLS. Argo CD’s UI stays behind a port-forward.

Parity gaps

The emulator is not AWS and one node is not a cluster.

What is fakedWhat it costs
IAMLocalStack authorises nothing: any credential works and no bucket policy is read. The encryption and public-access blocks the Terraform declares are recorded and never enforced, so a rule that would fail in a real account passes here
Workload identityThe pod reads a static key pair from a Secret committed to gitops/. IRSA needs AssumeRoleWithWebIdentity, which the app’s S3 client does not implement — that move is an application change, not a manifest change
Service discovery for “AWS”A selectorless Service, bound to the emulator by an EndpointSlice that bootstrap generates because Docker allocates the address. It is the one piece of cluster state outside git, it goes stale on every emulator restart, and the symptom is a readiness timeout that reads as a broken app. make aws-endpoint is the fix
The edgeNo hostname, no TLS block, no cloud load balancer. ingress-nginx itself is retired upstream and its supported table stops one minor below this cluster
Scale and failureOne node, two replicas, no traffic. Scheduling, eviction and a node going away are never put to the test, so nothing here tells you the deployment survives them

Inspection & reset

make status asks the cluster and containers, never the manifests — it names an unbound policy or a stale emulator address. make down keeps the Terraform state volume; make down-purge discards it. The split is deliberate — the command typed by habit must not be the one that loses state.

Where to look
  • tarmac/Makefile — every verb the platform has, and the order up runs them in
  • tarmac/scripts/ — one script per step, each safe to re-run, and versions.sh where every fetched pin lives
  • tarmac/kind/cluster.yaml — the single node, its digest pin and the 8080 mapping
  • tarmac/localstack/docker-compose.yml — the AWS stand-in, and which services it bothers to emulate
  • tarmac/scripts/status.sh — live state rather than desired state, including the stale-address check
