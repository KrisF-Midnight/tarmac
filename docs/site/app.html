Chapter 1

The app

A deliberately dull service whose only job is to prove the road works — and to fail visibly when something behind it is broken.

Moving parts

Bun is the runtime, the HTTP server and the S3 client in one — no framework, no AWS SDK. React renders the page, TypeScript throughout, bun test for the suite.

Interface & runtime

Bun serves the JSON API and the React page from one process — no proxy, no second container. Unmatched paths return the page too.

RouteWhat it answers
/*The React page, which fetches the greeting rather than hardcoding it
/api/greetingThe greeting as JSON, or 503 when the source is unreachable
/healthzLiveness. 200 always, touching nothing external
/readyzReadiness. Reads the greeting, 503 when it cannot

Build

There is no build step: the image ships source, and Bun bundles the HTML entrypoint at startup. The base image is pinned by digest, the hash of the exact bytes.

Config & dependencies

A bucket name in the environment switches the greeting from a built-in string to an object in S3. It is read per request, so editing it needs no redeploy.

Health & failure

Failing liveness restarts the container, and a restart cannot fix someone else’s bucket. /healthz therefore touches nothing external, pinned at 200 by a test while the source is broken. Readiness reads the object; a pod that cannot leaves the load balancer.

Identity

At runtime it holds one S3 key pair, handed to it by the environment. It carries no cluster credential, and nothing in the repo names Kubernetes.

Where to look
  • greeter/src/server.ts — the routes, and the probe split
  • greeter/src/greeting.ts — S3 or environment, chosen at startup
  • greeter/test/server.test.ts — the broken-source cases
  • greeter/Dockerfile — the digest pin, and why no bundle is built
  • greeter/infra/ — one call into the platform module, and the greeting string itself
